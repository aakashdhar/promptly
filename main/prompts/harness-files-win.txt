How Claude Code works headless (use only these features):
- `claude -p` runs one agent session and exits. Useful flags: `--model sonnet|opus|haiku`, `--permission-mode acceptEdits` (edits files without asking), `--allowedTools "Read Edit Bash(npm test:*)"`, `--max-turns N`. Pass the prompt on stdin, never as an argument (`claude` may be a .cmd launcher that mangles long or quoted arguments): `Get-Content -Raw .harness/PROMPT.md | claude -p --permission-mode acceptEdits`.
- Hooks go in `.claude/settings.json`: `{"hooks": {"PreToolUse": [{"matcher": "Edit|Write", "hooks": [{"type": "command", "command": "powershell -NoProfile -ExecutionPolicy Bypass -File .harness/guard.ps1"}]}]}}`. Hook commands always start PowerShell like that, with forward slashes in the path. Events: PreToolUse, PostToolUse, Stop. A hook command gets the tool call as JSON on stdin: read it with `$in = [Console]::In.ReadToEnd() | ConvertFrom-Json` (`$in.tool_input.file_path`, `.content`, `.new_string`, `.command`). Exit code 2 blocks the call and its stderr is shown to the agent, so say why and what to do instead: `[Console]::Error.WriteLine('...'); exit 2`. Use hooks for guardrails that must never be broken.
- Subagents go in `.claude/agents/<name>.md`: YAML front matter with `name`, `description`, `tools` (for example `Read, Grep, Bash`) and optionally `model`, then the agent's instructions. The main agent calls one when its prompt says "use the <name> agent".
- Parallel agents each need their own checkout: `git worktree add -B <branch> ../<dir> <base>`.

Rules for the harness:
- The loop, the checks and every stop condition are enforced by the PowerShell script, not only asked for in a prompt. The script runs the checks itself after each pass.
- Memory between passes lives in `.harness/PROGRESS.md`. Each pass reads it first and adds one line at the end. The last run writes a short summary there.
- Scripts are `.ps1` files for Windows PowerShell 5.1, which every Windows 10 and 11 PC has: no `&&` or `||` between commands, no ternary `? :`, no `??`, no `-Parallel`. Start each script with `$ErrorActionPreference = 'Stop'` and `$OutputEncoding = New-Object System.Text.UTF8Encoding $false` (so text piped to `claude` keeps its accents). After every native command (`claude`, `git`, `npm`) check `$LASTEXITCODE`. Use `Join-Path` for paths, `Get-Content -Raw` and `Set-Content -Encoding UTF8` for files, `ConvertFrom-Json` for JSON, and `[Diagnostics.Stopwatch]::StartNew()` for time limits. Write scripts in plain ASCII: PowerShell 5.1 reads a file without a byte-order mark in the ANSI code page.
- Keep harness files under `.harness/`, except `.claude/settings.json` and `.claude/agents/`. Put shared functions in `.harness/common.ps1` and dot-source it: `. (Join-Path $PSScriptRoot 'common.ps1')`.
- Write only the files this plan needs: 3 to 5 for a simple loop, at most 8 for a pipeline. Keep each file short and to the point, under 60 lines; put shared functions in one file instead of repeating them. Every file complete, no "..." or "rest of the file".
- Where a gap has no answer, write `TODO(<gap label>)` in the file so the user can find it.
- To tell the user something (stuck, finished) show a Windows notification with this function (built in, no modules to install; it never stops the harness if notifications are off):
  function Send-Notice([string]$Text) {
    try {
      $null = [Windows.UI.Notifications.ToastNotificationManager, Windows.UI.Notifications, ContentType = WindowsRuntime]
      $xml = [Windows.UI.Notifications.ToastNotificationManager]::GetTemplateContent([Windows.UI.Notifications.ToastTemplateType]::ToastText02)
      $lines = $xml.GetElementsByTagName('text')
      $null = $lines.Item(0).AppendChild($xml.CreateTextNode('Harness'))
      $null = $lines.Item(1).AppendChild($xml.CreateTextNode($Text))
      $app = '{1AC14E77-02E7-4E5D-B744-2EB1AE5198B7}\WindowsPowerShell\v1.0\powershell.exe'
      [Windows.UI.Notifications.ToastNotificationManager]::CreateToastNotifier($app).Show([Windows.UI.Notifications.ToastNotification]::new($xml))
    } catch { Write-Host "Harness: $Text" }
  }
