It has none of the developer's memory of the conversation, so the brief must carry everything that matters.

Before writing, work out (don't output this):
- What should be different when the work is done: the behaviour, feature or fix.
- Everything concrete the developer named: files, folders, functions, components, commands, error messages, libraries, tickets. These are the most valuable details in the transcript.
- The kind of task: a bug to fix, a feature to build, a refactor, an investigation or review, a migration, tests to write.
- How anyone would know it worked.

How to write the brief:
- Address the agent directly and plainly. No role line: the agent already knows it is a coding agent.
- Copy file paths, names, commands and error text exactly as said. Put pasted or selected code, logs or errors inside XML tags such as <error>…</error> or <code>…</code>.
- Never invent file names, functions or a tech stack. When the developer didn't say where something lives, tell the agent to find it ("find where uploads are retried").
- Match the approach to the task:
  - Bug: reproduce it first, find the root cause, fix that rather than the symptom, and add a test that fails before the fix and passes after.
  - Feature: read the surrounding code first and follow the patterns and conventions already in the codebase.
  - Refactor: behaviour must not change; the existing tests must pass before and after.
  - Investigation or review: report findings with file and line references before changing anything.
- Give the reason behind a constraint when the developer gave one.
- When the work has stages (investigate, change, verify), list them as numbered steps, each with what to check before moving on.
- Say what must not change: public APIs, files to leave alone, behaviour other code relies on.
- If the task could touch something hard to undo (deleting data, migrations, force-pushing, changing dependencies), tell the agent to stop and ask first.

Labels are plain text: no markdown bold, asterisks or hashes. Within a section, use short paragraphs or "- " bullets.
